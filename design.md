# Design: Tracker

## 1. Архитектура приложения

Приложение реализуется как автономный HTML-файл:

- `index.html` — структура интерфейса, CSS и JavaScript.
- Локальные файлы библиотек — картографические и вспомогательные зависимости.
- IndexedDB — постоянное хранилище пользовательских данных.

Внешние CDN и API-ключи не используются.

Картографические тайлы OpenStreetMap загружаются через интернет.

### Логические компоненты

1. Map View — интерактивная карта.
2. Cards View — каталог карточек.
3. Place Editor — добавление и редактирование места.
4. Visit Editor — информация о посещении.
5. Tracker — статистика и прогресс.
6. Category Manager — управление категориями.
7. Storage Manager — IndexedDB и резервное копирование.

Все компоненты работают с единой моделью данных.

## 2. Структура данных

Фотографии хранятся отдельно от основного объекта места, чтобы не перегружать записи каталога.

## 3. IndexedDB

Предусмотреть следующие object stores:

### places
Хранение основных объектов Place.

### categories
Хранение стандартных и пользовательских категорий.

### photos
Хранение фотографий в формате Blob.

Для фотографий предусмотреть индекс по `placeId`.

Все изменения данных должны записываться в IndexedDB.

Изменения связанных записей должны выполняться транзакционно, где это необходимо.

Интерфейс должен учитывать результат сохранения: нельзя считать изменение сохранённым до успешного завершения операции IndexedDB.

При ошибке записи необходимо:
- Сохранить несохранённое состояние в памяти.
- Показать понятное уведомление.
- Предупредить пользователя о риске потери данных.
- Не выполнять молчаливый сброс пользовательского состояния.

## 4. Единый источник данных

Карта, карточки и статистика используют одни и те же записи Place.

Фильтры и поиск формируют производные представления данных и не изменяют исходные объекты.

Разделение:
- Полный набор мест — источник данных.
- Активный фильтр — условия отображения.
- Отображаемый список — результат фильтрации.
- Статистика — расчёт по полному набору мест.

## 5. Расчёт статистики

Обозначения:

- `N` — общее количество мест.
- `V` — количество посещённых мест.
- `W` — количество запланированных мест.

Формулы:

`N = count(all places)`

`V = count(status === "visited")`

`W = count(status === "wishlist")`

`progress = N === 0 ? 0 : round(100 * V / N)`

Должно выполняться:

`N = V + W`

Статистика пересчитывается после:
- Добавления места.
- Удаления места.
- Изменения статуса.
- Импорта резервной копии.

Смена фильтра, режима отображения или поискового запроса не влияет на статистику.

## 6. Сортировка и Drag & Drop

Каждое место имеет поле `sortOrder`.

Порядок карточек определяется этим полем в соответствующем списке.

При перемещении карточки:
1. Определяется исходный список.
2. Определяется целевой список.
3. Определяется позиция вставки.
4. При необходимости меняется статус.
5. Пересчитываются позиции карточек.
6. Изменения сохраняются в IndexedDB.

При переносе между списками:
- wishlist → visited;
- visited → wishlist.

Позиции внутри каждого списка должны оставаться последовательными и однозначными.

Визуальное поведение:
- Подсветка позиции вставки.
- Плавное перемещение карточек.
- Автопрокрутка при приближении к границам списка.
- Поддержка сенсорного управления.
- Разделение жеста перетаскивания и обычного нажатия.

Альтернативное управление:
- Изменение статуса через действие в карточке.
- Изменение порядка посредством доступных действий перемещения вверх/вниз.

## 7. Картографический слой

Рекомендуемая библиотека: Leaflet, подключённая локально.

Источник тайлов:

`https://tile.openstreetmap.org/{z}/{x}/{y}.png`

Начальные координаты центра Москвы:

`55.7558, 37.6173`

Маркеры:
- Wishlist — один визуальный стиль.
- Visited — другой визуальный стиль.

Для большого количества мест использовать кластеризацию через локально подключённую библиотеку Leaflet.markercluster.

При нажатии на маркер отображать:
- Название.
- Категорию.
- Адрес.
- Статус.
- Краткий комментарий.

Выбор точки на карте при создании места должен передавать широту и долготу форме.

При недоступности тайлов картографический слой должен показывать сообщение, не блокируя остальные части интерфейса.

Атрибуция OpenStreetMap должна оставаться видимой.

## 8. Интерфейс

### Главный экран

Основной элемент — карта.

Предусмотреть:
- Переключение «Карта» / «Карточки».
- Счётчики статистики.
- Индикатор прогресса.
- Кнопку добавления места.
- Доступ к управлению категориями.
- Доступ к экспорту и импорту.

### Режим карточек

Верхняя панель:
- Все места.
- Хочу посетить.
- Посетили.

Дополнительные элементы:
- Поисковая строка.
- Фильтр категорий.
- Сортировка согласно сохранённому порядку.

Карточка:
- Фотография или заглушка.
- Название.
- Категория.
- Адрес.
- Статус.
- Действия редактирования и удаления.

Для посещённых мест дополнительно отображать оценку и краткий отзыв при наличии.

### Форма места

Поля:
- Название.
- Адрес.
- Координаты.
- Категория.
- Комментарий.
- Статус.

Координаты можно задать выбором точки на карте или редактированием существующих значений.

### Форма посещения

Поля:
- Дата посещения.
- Фотографии.
- Впечатления.
- Оценка от 1 до 5 звёзд.

## 9. Начальные данные

Предусмотреть демонстрационный набор мест с настоящими координатами Москвы.

Обязательные записи:

| Название | Координаты (широта, долгота) | Категория | Статус |
|---|---|---|---|
| Парк «Зарядье» | 55.7517, 37.6289 | Парки | wishlist |
| ГУМ | 55.7547, 37.6214 | Другое | visited |

Дополнить несколькими примерами других реальных мест Москвы.

Начальные данные должны загружаться только при отсутствии ранее сохранённых пользовательских данных.

## 10. Резервное копирование

Экспорт должен формировать единый файл резервной копии, содержащий:
- Все места.
- Все категории.
- Все фотографии.
- Версию формата резервной копии.

Фотографии необходимо сериализовать в формат, пригодный для восстановления бинарных данных.

Импорт:
1. Чтение файла.
2. Проверка структуры и версии.
3. Проверка обязательных полей.
4. Проверка ссылочной целостности фотографий.
5. Подтверждение замены текущих данных.
6. Транзакционное восстановление.

При неудачном импорте существующие данные должны оставаться неизменными.

## 11. Адаптивность

Минимальная поддерживаемая ширина — 390 px.

На мобильных устройствах:
- Основные действия должны оставаться доступными.
- Карта должна занимать доступную площадь.
- Каталог должен адаптироваться к узкому экрану.
- Карточки должны располагаться без горизонтальной прокрутки.
- Формы должны оставаться удобными для сенсорного управления.

## 12. Визуальная концепция

Общий стиль:
- Романтичный и уютный.
- Преимущественно розовая палитра.
- Мягкие пастельные оттенки.
- Светлые поверхности карточек.
- Аккуратная типографика.
- Ненавязчивые иконки.
- Плавные анимации.
- Минимум декоративных элементов, не несущих функциональной нагрузки.
